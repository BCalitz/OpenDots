# 1.1 Home: the assistant and today

The first screen. The assistant is on the left with a call button and the log. The day is on the right, laid out across the screen, with the items that need you made impossible to miss.

Screen: **2 · Home** on the [design canvas](https://claude.ai/artifact/C8YuNty1R1zDMZhgmg95VX). Follow its layout and wording. Use the styles already in `src/client/style.css`; do not add a UI library.

## Today

- The app opens on a chat. Flagged items live in the Inbox: the brief (`src/client/InboxBrief.tsx`), proposals (`InboxProposals.tsx`) and waiting on others.
- The data exists: proposals (`platform.proposals`, `GET /api/proposals`), pending approvals (`platform.approvals.pending()`), waiting items (`GET /api/discovery/waiting`), and the assistant's main chat thread.

## Build

### 1. `GET /api/today`

Code builds the list. No model is called.

Put the types in `src/shared/today-types.ts`:

```ts
interface TodayView {
  date: string; // local date in the owner's time zone
  now: TodayItem[]; // at most 2
  moreNow: number; // urgent items that did not fit in `now`
  decide: TodayItem[];
  waiting: TodayItem[];
  day: DayEntry[]; // empty until 2.1 adds the calendar
  quiet: { read: number; kept: number; sent: number }; // since the last local midnight
  status: 'ok' | 'paused' | 'no_accounts' | 'no_judge' | 'account_error';
}

interface TodayItem {
  id: string; // "proposal:<id>", "approval:<id>" or "waiting:<id>"
  kind: 'proposal' | 'approval' | 'waiting';
  title: string;
  who: string | null; // "Thandi Nkosi, Acme Ltd"
  why: string; // one sentence, built by code
  due: string | null; // "Due tomorrow", "You said Friday"
  ready: string | null; // "Draft reply is ready"
  urgency: Urgency | null;
  threadId: string | null;
  eventId: string | null;
  actions: TodayAction[]; // in display order; the first is the main button
}
```

Put the builder in `src/server/today.ts` as a pure function, `buildToday(inputs, now)`, so it can be tested without a database.

**What goes where:**

| Source                                                | Section   |
| ----------------------------------------------------- | --------- |
| Open proposal, urgency "within hours" or "today"      | `now`     |
| Pending approval whose item is urgent in the same way | `now`     |
| Any other open proposal or pending approval           | `decide`  |
| Waiting item past its follow-up time                  | `waiting` |
| Snoozed, dismissed, resolved or muted                 | Left out  |

A proposal and an approval about the same item appear once, as the approval, since that is the next thing to decide.

**Order:** within a section, by urgency, then importance, then oldest first. `now` holds the first two; the rest are counted in `moreNow` and listed first in `decide`.

**The `why` sentence** is built from what discovery stored for the item, never written by a model. Start with these templates and keep them in one file, since 5.4 extends them:

- A reply is asked: "She is asking for a reply." With a count when earlier items in the same thread exist: "She has asked twice."
- A decision is asked: "Only you can decide this."
- Urgency: "Needed by tomorrow."
- A focus matched: "About GreenBasket, which you are focusing on."
- Waiting: "You asked 5 days ago."

Use the person's name where a pronoun would be a guess.

**Actions** map to routes that exist:

| Item     | Actions                                                                                 |
| -------- | --------------------------------------------------------------------------------------- |
| Proposal | Review (open the item), Prepare, Handle, Later (`snooze`), Not important (`dismiss`)    |
| Approval | Review, Approve, Decline, and Always allow this when the tool's risk is `low` (see 1.2) |
| Waiting  | Review the follow-up, Wait longer                                                       |

### 2. The home view

New files in `src/client/`: `HomeView.tsx`, `AssistantPanel.tsx`, `TodayBoard.tsx`, `TodayCard.tsx`. Home is the default view and the **Today** tab.

**Assistant panel (left, about 400px):**

- The mascot, a status line ("Ready. 5 things need you, 2 of them today."), and the button **Call and talk through today**. Until 1.3 is built it starts the call that exists today.
- The log: the assistant Dot's main thread, shown with the existing transcript components (`ChatTranscript.tsx`, `useThread.ts`). Call receipts and discovery cards already render there.
- A text box at the bottom. Typing is always available and works as chat does now.

**Today board (right):**

- A heading with the date and one line about the day.
- **Needs you now:** one or two large filled cards, side by side. The first uses the dark fill, the second the amber fill, as on the canvas. Each has the due label, who, the title at 22px, the why line, the ready line and a main button at least 48px high. When `moreNow` is above zero, a line under the cards says "3 more are urgent" and scrolls to them.
- Three columns below: **Decide**, **Waiting on others**, **Your day**. Until 2.1, Your day says "Connect a calendar to see your day here."
- A footer: "Since yesterday I read 46 new items, kept 41 out of your way, and sent nothing." with a link to Activity.

The board refreshes when the assistant's thread receives an event and every 60 seconds. An action updates its card at once and rolls back with a message if the request fails.

**Review** opens the item (screen **5 · One item** on the canvas): why you are seeing it, what the person wrote, the draft or the exact action, the choices, the person, and what the assistant did. Build it as `ItemView.tsx` from the data the Inbox item view already loads (`GET /api/inbox/events/:id`, the proposal and its thread).

## States

| State                        | What the board shows                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| Loading                      | Card outlines in the final layout, so nothing jumps                     |
| Nothing needs you            | "Nothing needs you right now." and the quiet line. No empty columns     |
| Only non-urgent items        | No "Needs you now" row; the three columns move up                       |
| Paused                       | A banner with **Resume**; the list as it was when paused                |
| No accounts                  | "Connect your mail so I can start" with a button to Accounts            |
| Jev key missing              | "I can't judge new items until TypeSafe is set up" with a link to setup |
| An account's sign-in expired | A line naming the account with **Reconnect**                            |
| Request failed               | The last list, greyed, with **Try again**                               |

At narrow widths the assistant panel goes above the board, the two large cards stack, and the three columns stack.

## Not in this spec

Calendar entries (2.1), promises you made (2.3), reminders (2.4), the full "Why this?" with corrections (5.4), and the People page (5.1).

## Tests

- `buildToday`: sectioning, ordering, the cap of two, `moreNow`, one row for a proposal and approval about the same item, and that snoozed, dismissed and muted items are left out.
- Each `why` template, including the count of earlier asks.
- `GET /api/today` returns each `status`.
- The home view renders each state in the table, and an action that fails rolls back.
