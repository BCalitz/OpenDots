# 6.8 Checks against the live services

Every test runs on fixtures, so a provider changing its API, or a change here that only breaks against the real service, is found by the owner in daily use. This adds a small set of checks that talk to the real services, run on a schedule and before a release.

## Today

- `.github/workflows/ci.yml` runs format, lint, typecheck, tests and a build on every push. No step uses a real key.
- The README says live chat was last verified before the engine moved to OpenDots' own code, and that Slack and spoken delegation have never been verified against the live services.

## Build

### 1. A live suite

- Put the checks in `tests/live/`, one file per provider, run by `npm run test:live` with its own Vitest config. `npm test` must never pick them up.
- Each check reads its keys from the environment and **skips, with a printed reason, when a key is missing**. A skipped check is not a pass: the run's summary lists what was skipped.
- Each check does the smallest real thing and cleans up after itself.

| Check                | What it does                                                                                | Needs                            |
| -------------------- | ------------------------------------------------------------------------------------------- | -------------------------------- |
| Model                | One chat turn through `DotEngine` with a tool call, and one streamed answer                 | `OPENAI_API_KEY`, `OPENAI_MODEL` |
| TypeSafe             | One `judge` call on a fixed, made-up mail; asserts the answer shape the classifier expects  | `TYPESAFE_API_KEY`               |
| Gmail                | Search, read one message, save a draft, delete that draft                                   | A test account's refresh token   |
| Outlook and calendar | Search, read one message, list events, save a draft, delete that draft                      | A test account's refresh token   |
| Teams                | List chats, read one chat                                                                   | A test account's refresh token   |
| Slack                | `auth.test`, and one message posted to and read from a test channel                         | A test workspace's tokens        |
| Speech               | Opens a realtime session and closes it; asserts the session accepts the tools the call uses | The speech key                   |
| Web research         | One search through the configured provider                                                  | None for light use               |

- **Use test accounts only.** No check reads the owner's real mailbox, and the made-up mail sent to TypeSafe contains no real content.
- **No check sends mail or a chat message to a person.** Drafts are saved and deleted; the Slack message goes to a channel that exists for this.
- A check fails with the provider's own error text, shortened, and never prints a key or a token.

### 2. A scheduled workflow

- Add `.github/workflows/live.yml`: runs `npm run test:live` daily and on `workflow_dispatch`. It never runs on pull requests, so a fork cannot reach the secrets.
- Keys are repository secrets. The workflow needs no database beyond the same Postgres service the CI job uses.
- When a run fails, it opens an issue titled "Live check failed: Outlook" or adds a comment to the open one, and closes the issue when the check passes again.

### 3. A release checklist

Some things cannot be checked without a person. Add `docs/RELEASE.md` with a short list to tick before a release:

- Run the live workflow and read the skipped list.
- One real call: start it, walk through two items, decide one by voice and one by tap, end it, and read the receipt.
- One Dot computer session: open a page, save a file, stop and start, and confirm the file is still there.
- Connect a fresh Google account and a fresh Microsoft account through the sign-in screens.
- Install from scratch following [SETUP.md](../SETUP.md).

Each line says what to look for and where a failure usually comes from.

### 4. Tell the truth in the README

Replace the dated "verified on" sentences in the README with a line that points to the live workflow's status and to `docs/RELEASE.md`.

## Tests

- With no keys set, `npm run test:live` exits successfully and lists every check as skipped.
- `npm test` does not run anything under `tests/live/`.
- A check that fails prints no secret: a test feeds it a fake key and asserts the output does not contain it.
