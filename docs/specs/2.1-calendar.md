# 2.1 Calendar as a source

OpenDots reads your calendar so the home screen can show your day, meetings can be prepared (2.2), and "you are free at 10:00" is a fact and not a guess. This spec only reads. Changing a meeting is a `meeting` action and already asks every time (1.2).

## Today

- The Outlook connector has a `list_events` tool and asks for `Calendars.Read` (`src/server/connectors/microsoft.ts`). Nothing calls it on a timer.
- The Gmail connector has no calendar tool and no calendar scope (`src/server/connectors/gmail.ts`).
- `calendar.changed` is already an event kind (`src/server/inbox/source.ts`), and account sources are read by `AccountListSource` (`src/server/inbox/account-source.ts`).
- The home screen's **Your day** column is empty until this is built (`day: DayEntry[]` in spec 1.1).

## Build

### 1. Google Calendar

- Add the read-only calendar scope to `GMAIL_SCOPES` and a `list_events` tool with the same arguments and result shape as Outlook's: `start`, `end`, `limit`; each event has an id, title, start, end, all-day flag, attendees (name and address), organiser, location, online-meeting link, the owner's response, and whether it is cancelled.
- An account connected before this change has no calendar scope. Its `list_events` call fails with "Reconnect Google to add your calendar", and Accounts shows that line with **Reconnect**. Mail keeps working.
- Give both `list_events` tools the risk `read` once 1.2 step 3 is merged.

### 2. A calendar reader

- Add a `calendar` reader beside `gmail`, `outlook` and `teams` in `account-source.ts`, and let an account have a calendar source next to its mail source. Connecting an account creates both; discovery settings can turn the calendar off.
- Each poll reads from now to 14 days ahead.
- Poll every 5 minutes by default.

### 3. The `calendar_events` table

The poll result replaces what is stored, so the table always holds only the next 14 days.

```sql
CREATE TABLE calendar_events(
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  account_id TEXT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  external_id TEXT NOT NULL,
  title TEXT NOT NULL,
  starts_at BIGINT NOT NULL,
  ends_at BIGINT NOT NULL,
  all_day BOOLEAN NOT NULL,
  attendees TEXT NOT NULL,      -- JSON list of { name, address, response }
  organiser TEXT,
  location TEXT,
  link TEXT,
  response TEXT,                -- the owner's: accepted, tentative, declined, none
  external BOOLEAN NOT NULL,    -- any attendee outside the owner's domains
  fingerprint TEXT NOT NULL,    -- hash of start, end, title, attendees, cancelled
  updated_at BIGINT NOT NULL,
  UNIQUE(account_id, external_id)
);
CREATE INDEX calendar_events_day ON calendar_events(owner_id, starts_at);
```

In one transaction per poll: upsert what came back, delete rows in the window that did not come back, and delete rows that ended more than a day ago.

### 4. Events for changes

Write a `calendar.changed` inbox event only when something the owner would care about changed, found by comparing fingerprints:

| Change                                 | Event title                                  |
| -------------------------------------- | -------------------------------------------- |
| New meeting the owner did not create   | "New meeting: GreenBasket weekly, Thu 10:00" |
| Time moved                             | "Moved: GreenBasket weekly, now Thu 11:00"   |
| Cancelled                              | "Cancelled: GreenBasket weekly"              |
| Invitation not answered, within 2 days | "Not answered: GreenBasket weekly"           |

The first poll of a calendar writes no events. Attendee and title edits alone write none.

These events go through discovery like mail. Attendee addresses are matched to entities with the free tiers only (exact alias, then address and domain), so a meeting links to the people in it.

### 5. The day

- Add `GET /api/calendar/day?date=` returning that local day's events and the free gaps between 08:00 and 18:00 that are 30 minutes or longer. Working hours are a setting, with those defaults.
- `buildToday` (1.1) fills `day` from it: each meeting, each gap ("Free until 16:00"), and for a gap, how many `now` items fit, counting 20 minutes each.
- The home heading's one line about the day uses the longest gap.

### 6. For the assistant

Add a read-only tool, `my_calendar`, for chat and calls: events between two times, from the table for the next 14 days and from `list_events` beyond that.

## States

| State                            | What shows                                                     |
| -------------------------------- | -------------------------------------------------------------- |
| No calendar connected            | Your day: "Connect a calendar to see your day here"            |
| Google account without the scope | Your day: "Reconnect Google to add your calendar"              |
| No meetings today                | "No meetings today"                                            |
| The poll is failing              | The last known day, with "Calendar last read at 09:40"         |
| Two calendars                    | One merged day; each entry names its account when they overlap |

Declined and cancelled meetings are left out of the day. All-day events are listed above the timed ones and do not count as busy.

## Not in this spec

Meeting prep (2.2), changing or creating meetings, calendars other than the primary one, and time zones other than the owner's setting.

## Tests

Use connector fixtures.

- The Google and Outlook readers return the same event shape.
- A poll upserts, removes what disappeared, and never touches another account's rows.
- Each row of the change table writes one event; an unchanged poll writes none; the first poll writes none.
- A recurring meeting writes one event per changed occurrence, not one per poll.
- Free gaps: back-to-back meetings, overlapping meetings, an all-day event, and a day with none.
- An account without the calendar scope reports the reconnect message and its mail source keeps polling.
