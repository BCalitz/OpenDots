# 6.9 Costs in money

Insights shows tokens. This shows what the assistant cost this month in money, counts the calls that are not tokens, and warns before a limit is reached.

## Today

- `usage_ledger` holds one row per run: thread, Dot, model, input tokens, output tokens (`src/server/usage-store.ts`).
- Each Dot has a monthly token limit, and Insights shows tokens per Dot and whether the cap was reached (`src/shared/insight-types.ts`).
- Jev calls to TypeSafe, speech minutes and web searches are not recorded anywhere as usage.

## Build

### 1. Prices

- Add `src/server/prices.ts` with a table of known models: price per million input tokens and per million output tokens, in US dollars. Include the models the setup docs name.
- The owner can override or add prices in Settings, stored in the workspace settings. A model with no price is shown as "no price set" and is left out of totals, with a note saying so. Never guess a price.
- A currency setting: the code, and a rate against the dollar that the owner types in. No rate is fetched from the internet. Default: dollars.

### 2. Record the other costs

Add one table for usage that is not a model run.

```sql
CREATE TABLE usage_other(
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  kind TEXT NOT NULL,           -- jev, speech, search
  dot_id TEXT,
  units DOUBLE PRECISION NOT NULL,  -- calls, minutes, searches
  detail TEXT,                  -- for jev: which question set
  created_at BIGINT NOT NULL
);
CREATE INDEX usage_other_month ON usage_other(owner_id, created_at);
```

- **Jev:** one row per call, written where the classifier and memory call TypeSafe, with whether it was a judge call or a match call.
- **Speech:** one row per call when it ends, with its minutes.
- **Search:** one row per search.
- Each kind has a price per unit in the same price table, zero by default, set by the owner.

Add `owner_id` to `usage_ledger` in the same migration, filled with the install's owner.

### 3. The report

Extend the existing usage report with, for the current month and the one before:

- money per Dot, split into model, Jev, speech and search;
- the total, and the projected month-end total from the days so far;
- the three most expensive runs, each linking to its run in Insights;
- money by what the work was for, using the turn source that already exists: chat, calls, discovery, prepare, handle, schedules.

Insights shows money first and tokens under it.

### 4. A monthly budget

- A setting: a budget in the owner's currency, off by default.
- At 80% the home screen and the morning brief say so once: "This month has cost R 412 of your R 500 budget."
- At 100%, **discovery and chat keep working**. The owner chooses in Settings what stops: nothing (the default), or background work only (schedules, prepare and suggestions), so an urgent mail is never missed because of a budget.
- The existing per-Dot token limit stays as it is.

## States

| State                    | What shows                                                         |
| ------------------------ | ------------------------------------------------------------------ |
| A model has no price     | Its tokens, "no price set", and a link to add one                  |
| No rate for the currency | Dollars                                                            |
| No usage yet             | "Nothing has run this month"                                       |
| Budget reached           | A banner saying what is and is not paused, with a link to Settings |

## Not in this spec

Billing users, per-user limits beyond the budget (6.3), and fetching prices or exchange rates automatically.

## Tests

- Cost of a run: tokens times price, for input and output, with an override taking priority.
- A model without a price is excluded from the total and reported as such.
- Jev, speech and search rows are written once per call, including when the call fails after being made.
- The projection for a month, on day 1, mid-month and the last day.
- The 80% notice is sent once per month.
- At 100% with "background only", a schedule does not run and a discovery judgment still does.
- Currency conversion uses the typed rate and rounds to two places.
